# ぷっくり立体 for YMM4

[![License](https://img.shields.io/badge/license-MIT-blue.svg)](#)
[![.NET](https://img.shields.io/badge/.NET-10.0-purple.svg)](#)
[![Release](https://img.shields.io/github/v/release/routersys/YMM4-Inflate.svg)](https://github.com/routersys/YMM4-Inflate/releases)

---

YukkuriMovieMaker4（YMM4）上で動作する、現在のフレームの不透明度を輪郭とみなし、輪郭の内側が広い所ほど高く膨らんだ面をポアソン方程式で求め、光源と質感を与えて元映像へ重ねる映像エフェクトプラグインです。
履歴フレーム、参照画像、学習済みモデルを使わず、入力された一枚の映像だけを処理します。
結果は入力映像と設定から決定論的に決まり、同じ環境と設定では常に同じ結果になります。
光の向きと仰角、環境光、光沢、映り込み、縁の光、素材の色を設定して、文字や図形をふくらんだ立体に見せられます。
強さ、高さ、光の向き、光の仰角、環境光、光沢、光沢の鋭さ、映り込み、縁の光、素材の色の10項目はアニメーションに対応しています。

## 概要

本プラグインはYMM4の映像エフェクトとして動作し、エフェクトの種類一覧では「ぷっくり立体」として表示されます。カテゴリは加工と装飾です。

入力された現在のフレームの不透明度から、不透明な部分を輪郭の内側とみなします。処理する範囲はこのエフェクトに入る映像を囲む矩形です。格子はこの範囲を縦横に区切ったセルの並びです。輪郭の内側のセルごとに、膨らみの大きさを表す値をポアソン方程式で求め、その値から高さを決めます。輪郭の内側が広い所ほど高く、狭い所ほど低くなります。高さの計算は、Sýkora らの論文「Ink-and-Ray: Bas-Relief Meshes for Adding Global Illumination Effects to Hand-Drawn Characters」（ACM Transactions on Graphics 2014）に基づきます。この論文は領域を膨らませる手順として、ポアソン方程式の解の平方根を高さとする方法を示しています。

次の画像は、ぷっくり立体を文字の画像に適用した例です。

![ぷっくり立体の作例](https://github.com/routersys/YMM4-Inflate/blob/main/docs/Inflate-example.png)

処理は3つの段階に分かれます。高さの計算は輪郭からポアソン方程式の解を求める段階です。描画は解から各画素の面の向きを求め、光と質感で色を決める段階です。合成は描いた像と入力映像を強さの割合で混ぜる段階です。画素の位置は動かさないため、輪郭の位置と形は入力映像のままです。

計算はComputeWeaveの計算シェーダーがDirect3D 12で実行します。YMM4のDirect3D 11側とComputeWeaveのDirect3D 12側は、共有テクスチャと共有フェンスで接続します。通常のフレーム処理では、CPUへ画素を読み戻さず、入力映像の変化の判定に使う4個の整数だけを読み戻します。入力映像の輪郭、大きさ、品質が変わらないフレームでは、高さの計算を再利用します。輪郭が同じで色だけが変わったフレームでも、高さの計算は再利用し、描画だけをやり直します。再利用の条件は「注意事項」にあります。

このエフェクトはAviUtl向けのEXO出力には対応していません。

## インストール方法

1. [Releases](https://github.com/routersys/YMM4-Inflate/releases/latest)ページから最新のプラグインファイル（`.ymme`）をダウンロードしてください。
2. YMM4が起動していないことを確認し、ダウンロードしたファイルを実行してインストールします。
3. YMM4を起動し、タイムライン上のアイテムに映像エフェクトを追加します。
4. 映像エフェクトの種類として「ぷっくり立体」を選択してください。

## 主な機能

### 1. 輪郭と格子

輪郭は入力された現在のフレームの不透明度だけから決めます。格子のセルが覆う画素の不透明度の平均が50%以上のセルを、輪郭の内側とします。外部マスクや手動の指定は必要としません。

格子の長辺のセル数は格子解像度と処理する範囲の長辺の画素数のうち小さいほうです。格子解像度は品質で決まり、「品質の選択」の表にあります。短辺のセル数は処理する範囲の縦横比に合わせて最も近い整数に丸め、1セル以上にします。

### 2. 高さの計算

各セルの高さを決める値 u は輪郭の内側で `−Δu = 1` を満たし、輪郭の外側と処理する範囲の外で0になる解です。セルの1辺の長さを1とします。Δはラプラシアンで、格子の上では、上下左右の4個の隣のセルの値の合計から、そのセルの値の4倍を引いた値になります。輪郭の内側が広いほど u は大きくなります。たとえば半径Rの円では、中心からの距離rで u は (R²−r²)/4 になり、中心で最大の R²/4 になります。

高さは高さの倍率に 2u の平方根を掛けた値です。円の断面は半楕円になり、高さの倍率が100%のとき中心の高さは半径の約0.71倍です。同じ形を縦横とも2倍にすると高さも2倍になります。細い線は低く、太い面は高くなります。

方程式は5点差分で離散化します。5点差分はセルの値と上下左右の4個の隣の値から二階微分を近似する方法です。隣が輪郭の外側か処理する範囲の外にあるときは、そのセルと隣の境の面で u が0になるように扱います。

### 3. マルチグリッド法による解法

方程式はマルチグリッド法のVサイクルで解きます。マルチグリッド法は格子を2×2のセルずつまとめて粗くした格子を何段も重ね、粗い格子で誤差を求めて細かい格子の解を補正する方法です。最も粗い格子は長辺が16セル以下になるまで重ねて作ります。粗い格子のセルはまとめる4セルのうち3個以上が内側なら内側とします。ちょうど2個のときは粗い格子での横位置と縦位置の和が偶数のセルだけを内側とします。隣り合う粗いセルは元のセルの間に内側どうしが接する面があるときだけ、隣として扱います。

Vサイクル1回の手順は次のとおりです。

1. 細かい格子で方程式の残差を求めます。残差は方程式の右辺から左辺を引いた値です。
2. 残差を粗い格子へ制限する操作を、最も粗い格子まで繰り返します。制限は4個のセルの残差の合計を粗いセルの値にする操作です。
3. 最も粗い格子では、ヤコビ法を256回繰り返して誤差を求めます。
4. 細かい格子へ順に戻りながら、誤差の補間と平滑化を行います。補間は粗い格子の値から線形補間で細かい格子の値を求める操作です。平滑化はガウス・ザイデル法の反復で、誤差のうち格子の間隔に近い細かい変動を減らす操作です。前平滑化は行いません。

ヤコビ法は全セルの値を同時に計算し直す方法です。各セルの値は直前の反復での上下左右の隣のセルの値と右辺から求めます。ガウス・ザイデル法はセルを市松模様に赤と黒へ分け、赤のセルをすべて更新してから黒のセルをすべて更新する方法です。この順序を赤黒順序付けと呼びます。黒のセルは更新した赤のセルの値を使って求めます。赤と黒を1回ずつ更新することを、1反復と数えます。

方程式を行列で Ax = b と書くと、解は二次形式 ½xᵀAx − bᵀx を最小にする x と一致します。最も細かい格子へ足す誤差には、倍率を掛けます。倍率は誤差の方向に沿ってこの二次形式が最小になる値で、0以上4以下です。この倍率により、誤差を足した直後の二次形式の値は、足す前より大きくなりません。Vサイクルの回数と、各格子で行う反復の回数は、「品質の選択」の表にあります。

### 4. 光と質感による描画

描画は画素ごとに次の順で色を決めます。入力の不透明度が0の画素は透明のままにします。

まず、面の向きを表す法線を求めます。画素の位置の u は周りの4セルの値から線形補間で求めます。u の傾きは中心差分で求めます。左右と上下のそれぞれで、1セルずつ離れた2点の値の差の半分です。高さ k√(2u) の傾きは、u の傾きに k/√(2u) を掛けた値になります。k は高さの倍率です。2u には0.0625を足し、輪郭の縁で傾きが大きくなりすぎるのを防ぎます。この高さの傾きの符号を反転した2成分と1を並べたベクトルを、長さが1になるように正規化したものが法線です。

次に、素材の色を決めます。素材の色の設定に応じて、明るさ0.9の白と入力の色を混ぜます。拡散反射の明るさは法線と光の向きの内積に0.35を足して1.35で割り、0から1に収めた値です。光と反対を向く面にも、わずかに明るさが残ります。全体の明るさは環境光に、拡散反射の明るさと「1から環境光を引いた値」の積を足した値です。素材の色にこの明るさを掛けます。

映り込みは法線で視線を反射させた向きに応じた環境の色を、照らした色へ混ぜます。環境の色は向きが上なら空の淡い青、下なら地面の暗い茶色で、その間は滑らかに変わります。混ぜる割合は映り込みの設定に、0.15と「1から奥行き成分を引いた値の3乗の0.85倍」の和を掛けた値です。奥行き成分は法線の画面に垂直な成分です。正面を向くと1になり、縁に近づくほど小さくなります。そのため、縁に近いほど強く映り込みます。

光沢は光の向きと視線の向きの中間を向くハーフベクトルを求め、法線との内積を0から1に収めてべき乗した値に、光沢の強さを掛けて足します。これはブリン・フォンの反射モデルと同じ求め方です。法線と光の向きの内積が0以下の面には足しません。指数は光沢の鋭さで決まり、0%で4、100%で1024です。縁の光は素材の色と白を半分ずつ混ぜた色に、縁の光の設定と「1から奥行き成分を引いた値」の3乗を掛けて足します。

最後に、色を0から1に収め、入力の不透明度を掛けて出力します。出力の不透明度は入力と同じです。この像は強さの割合で入力映像と混ぜて出力します。

### 5. 光源の設定

光の向きは光が来る向きの角度です。0°で上から、90°で右から、-90°で左から、180°と-180°で下から当たります。光の仰角は光が画面から立ち上がる角度です。0°で画面と平行に当たり、90°で正面から当たります。

環境光は光が当たらない面にも加わる明るさです。100%にすると、拡散反射による明るさの違いがなくなり、素材の色がそのままの明るさで照らされます。光沢、映り込み、縁の光は、これとは別に加わります。

### 6. 質感の設定

光沢は光源のハイライトの強さです。0%でハイライトを付けず、上げるほど明るくなります。光沢の鋭さを上げるほど、ハイライトは小さく鋭くなります。

映り込みは周囲の景色が表面に映る強さです。上を向いた面には淡い青、下を向いた面には暗い茶色が混ざります。縁の光は縁に近い所を明るくする光の強さです。

素材の色は入力の色を残す割合です。100%では入力の色のまま照らします。0%にすると、入力の色によらず白い素材として照らします。

### 7. 品質の選択

品質は格子の解像度、Vサイクルの回数、各格子で行う平滑化の反復回数をまとめて切り替えます。

| 品質 | 格子解像度 | Vサイクル | 平滑化の反復 |
|---|---:|---:|---:|
| 標準 | 1024 | 2回 | 3回 |
| 高品質 | 1536 | 3回 | 3回 |
| 最高品質 | 2048 | 4回 | 4回 |

格子解像度は格子の長辺のセル数の上限です。処理する範囲の長辺が格子解像度以下のときは、長辺の画素数がそのままセル数になり、格子の大きさはどの品質でも同じです。ただし、Vサイクルの回数と反復の回数は品質ごとに違います。品質を上げるほど、解は収束した解に近づきます。

## 制限事項

- AviUtl向けのEXO出力には対応していません。
- Direct3D 12デバイスを取得できない場合や、YMM4が使うDirect3D 11デバイスとの共有テクスチャおよび共有フェンスを作成できない場合は、エフェクトを適用せず入力映像を表示します。
- 描画には現在のフレームの色と不透明度だけを使用します。履歴フレーム、外部画像、学習済みモデルは使用しません。
- 処理する範囲の辺が1画素以上8192画素以下の入力に対応します。判定には、プロジェクトの解像度ではなく、処理する範囲の大きさを使います。条件を満たさない入力には、エフェクトを適用せず入力映像を表示します。
- 高さは陰影の計算にだけ使います。画素の位置は動かさないため、輪郭の形と位置は入力映像のままです。
- 処理する範囲の端に接する不透明な部分は、その端でも輪郭として扱います。端へ向かって高さが下がります。
- 処理量とGPUメモリ使用量は入力映像の画素数と品質に応じて増えます。

## 注意事項

- 処理負荷: 最高品質は格子解像度とVサイクルの回数が最も多いため、高品質と標準より処理負荷が高くなります。
- キャッシュ: 輪郭の判定に使う2個の整数と、色の判定に使う2個の整数は、毎フレームGPUで求めます。輪郭の整数は全画素の不透明度から、色の整数は全画素の色と不透明度から作ります。処理する範囲の大きさ、品質、輪郭の整数が、高さを計算したときと同じなら、高さの計算を再利用します。「高さ」、光源グループの3項目、質感グループの5項目は、高さの計算に影響しません。これらだけを変えても、高さの計算は再利用します。動画のように、直近に読み戻した2フレーム分の輪郭の整数が違うあいだは、輪郭が変わり続けているとみなします。このときは今のフレームの整数の読み戻しを待たず、毎フレーム高さを計算し直し、整数は次のフレームで読み戻します。輪郭が最後に変わったフレームの次のフレームでも、直近に読み戻した2フレーム分の整数はまだ違います。そのため、このフレームでも高さを計算し直し、その次のフレームから再利用します。輪郭が変わり続けるときは処理が重くなります。
- 描き直し: 高さの計算を再利用するフレームでも、色の整数、「高さ」、光源グループの3項目、質感グループの5項目のどれかが変わると、描画をやり直します。どれも変わらないフレームでは、描画も再利用します。強さだけを変えたフレームでは、描き直さず、合成の量だけを変えます。
- 強さ0%: 強さが0%のときは高さの計算も描画も行わず、入力映像をそのまま出力します。
- 再現性: 乱数と時間値は使用しません。同じ環境と設定では、常に同じ結果になります。
- 透明部分: 不透明度が0の画素は透明のままです。出力の不透明度は強さが100%のとき入力と同じです。強さが100%より小さいときは入力と描いた像を強さの割合で混ぜた値になります。
- 更新通知: エフェクトを最初に生成したときに、YMM4の実行中に一度だけ新しい正式版を確認します。更新情報を取得できない場合は通知せず、そのまま動作します。プレリリースは通知の対象に含めません。
- 不具合の自動送信: 想定していない例外が起きたときは、その内容を開発者へ自動で送信します。内容は「不具合の報告」に書いています。
- 本プラグインを使用する前に、YMM4のプロジェクトファイルのバックアップを作成することを推奨します。

## 不具合の報告

本プラグインは、想定していない例外が起きたときに、その内容を開発者へ自動で送信します。同意は求めず、常に送信します。

送信する情報は次のとおりです。

| 種類 | 内容 |
|---|---|
| 例外 | 型の完全名、メッセージ、スタックトレース |
| 発生位置 | モジュール名、関数名、ファイル名、行番号 |
| プラグイン | アセンブリ名、バージョン |
| 実行環境 | OSの名前とバージョン、.NETのバージョン、CPUのアーキテクチャ、論理プロセッサ数 |
| 識別子 | YMM4の起動ごとに決まるセッション識別子、報告ごとの識別子 |

メッセージとファイル名は、送信の前に置き換えを通します。置き換えるのは、Windowsのユーザー名、ユーザーフォルダー、AppDataのパス、マシン名、ドメイン名、メールアドレス、IPv4アドレスです。送信元のIPアドレスは受信側へ渡す手前で取り除いています。

映像の中身とプロジェクトの内容は送信しません。継続して個人を追跡する識別子も持ちません。セッション識別子はYMM4を起動し直すと別の値になります。

送信するのは想定していない例外だけです。YMM4が本プラグインのエフェクトを作るとき、フレームごとに更新するとき、入力をつなぎ直すとき、破棄するときと、Direct2Dがシェーダーの定数を書き込むときに起きた例外を報告し、その後はYMM4へそのまま渡します。更新の確認では、更新情報の取得と比較で起きた例外は報告しません。通知の文を組み立てて表示するときに起きた例外は報告し、YMM4へは渡しません。画面の操作やバックグラウンドの処理で未処理になった例外も報告しますが、本プラグインのコードが関わる例外に限ります。本プラグインの外で起きた例外は送信しません。

次の失敗は送信しません。

| 種類 | 例 |
|---|---|
| 効果をかけないだけで済ませるもの | Direct3D 12デバイスを取得できない、YMM4のDirect3D 11デバイスとの共有テクスチャや共有フェンスを作成できない、処理する範囲の辺が8192画素を超えるときに、エフェクトを適用せず入力映像を表示したとき |
| 更新の確認の通信の失敗 | manjubox.netとGitHubのどちらへも接続できない |

送信できなかった報告はYMM4のユーザーフォルダーへ退避します。次にYMM4を起動したあと、本プラグインのエフェクトを生成するか、同じくYMM4-Telemetryで報告する別のプラグインが動き始めると、退避した報告を1回の起動で10件まで送り直します。送信も再送も非同期に行うため、通信を待って起動と描画が遅くなることはありません。

実装は [YMM4-Telemetry](https://github.com/routersys/YMM4-Telemetry) をサブモジュールとして取り込んでいます。
